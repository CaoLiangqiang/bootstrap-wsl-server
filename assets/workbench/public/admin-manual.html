WSL 服务器
主机端管理员手册

用于管理 Windows NAT 网络下的 WSL __DISTRO__ SSH 服务器。工作台只绑定本机回环地址；局域网访问通过 Windows TCP 端口转发和 Private/LocalSubnet 防火墙规则实现。

1. 架构与边界

其他电脑LAN SSH 客户端
Windows监听 TCP __SSH_PORT__
portproxy转发至 127.0.0.1:22
WSL __DISTRO__sshd:22
工作台127.0.0.1:4173，只允许本机浏览器访问。
WSL 网络默认 NAT；不要为 Docker 或 SSH 启用 mirrored networking。
认证允许 __WSL_USER__ 使用密码或公钥登录，root 仍禁止。
动态地址：Windows 有线/WLAN 地址通常来自 DHCP，实际连接前以工作台显示为准。

2. 启动与查看

Windows 登录时的任务会启动 __DISTRO__；用户级 systemd 随后启动工作台和自检 timer。浏览器打开：

http://127.0.0.1:4173

手动查看和重启：

systemctl --user status wsl-server-workbench
systemctl --user restart wsl-server-workbench
systemctl --user is-active wsl-server-workbench-health.timer
systemctl --user list-timers --all | grep wsl-server-workbench

查看服务日志：

journalctl --user -u wsl-server-workbench -f
journalctl --user -u wsl-server-workbench-health.service --since today

3. 日常操作

查看服务器

工作台顶部显示 SSH、NAT、认证和对外端口；“连接入口”给出每个 Windows LAN 地址的完整 SSH 命令；“安全边界”显示允许用户、认证方式、root 策略和防火墙范围。

修改密码

点击“访问管理 → 修改”。工作台只打开 Windows Terminal 的系统 passwd __WSL_USER__，密码输入发生在终端，不经过网页、Node 进程或日志。

录入登录公钥

本服务器不创建独立 Linux 账号，所有访问者共享 __WSL_USER__ 账号；每位访问者应使用自己的私钥。打开“访问管理 → 登录公钥”，选择对方提供的单行 .pub 文件，核对工作台显示的 SHA256 指纹后确认录入。工作台只接受公钥，只显示指纹和算法；私钥内容会被拒绝且不会保存。

录入操作只追加 ~/.ssh/authorized_keys，不重启或 reload sshd，已有 SSH 连接不会被中断。若 WebUI 不可用，可回退到：

bash ~/wsl-server-workbench/scripts/add-ssh-public-key.sh /path/to/user.pub

登记审计只记录结果、算法和指纹，不记录公钥正文：

journalctl --user -u wsl-server-workbench --since today | grep public-key-enrollment
工作台只绑定 127.0.0.1，没有独立登录认证；只在本机管理员浏览器中使用。持有已登记私钥的人都能以 __WSL_USER__ 身份获得该账号权限。

修改/停止端口

输入 1024-65535 的端口并点击“应用”，确认 Windows UAC 后，管理脚本会更新 portproxy 和 Private/LocalSubnet 防火墙规则。点击“停止局域网访问”只停止 Windows 入口，不关闭 WSL 内部 sshd。

其他电脑连接格式：

ssh -p __SSH_PORT__ __WSL_USER__@<Windows-LAN-IP>

4. 周期自检

用户级 timer 默认在 WSL 启动约 90 秒后执行，之后每 5 分钟一次；结果保存最近 7 天。工作台的“周期自检”面板显示最新状态、每个检查项、耗时和最近 24 个结果点。也可点击“立即自检”。

检查项严重级别通过条件
工作台 API严重本地 API 能返回 overview。
SSH 服务、默认路由、DNS严重systemd active、NAT default route 存在、resolver 有 nameserver。
Windows portproxy严重转发存在且 Windows 监听端口可见。
防火墙、登录任务、SSH 策略警告Private/LocalSubnet、登录任务存在、密码和公钥启用、root 禁止、用户受限。

自检原始记录位置：~/.local/state/wsl-server-workbench/health-history.jsonl。其中没有密码或私钥。

5. 访问记录

日志来自 WSL 的 journalctl -u ssh，页面解析为成功、失败和策略拦截。查看原始记录：

journalctl -u ssh --since '24 hours ago' --no-pager
journalctl -u ssh -f

当前策略同时允许密码和公钥。建议长期连接使用公钥，密码只用于首次登记、应急登录和修改密码。

6. 问题排查

工作台页面打不开

  1. 检查服务：systemctl --user is-active wsl-server-workbench。
  2. 检查监听：ss -lntp | grep 4173，应为 127.0.0.1:4173。
  3. 检查 API：curl http://127.0.0.1:4173/api/overview。
  4. 若 __DISTRO__ 未运行，从 Windows PowerShell 执行 wsl -d __DISTRO__ 后再重试。

自检显示 SSH 失败

systemctl status ssh --no-pager
sudo sshd -t
cat /etc/ssh/sshd_config.d/99-wsl-server.conf
sudo systemctl reload ssh.service

当前应看到 PasswordAuthentication yes、PubkeyAuthentication yes、PermitRootLogin no、AllowUsers __WSL_USER__。

局域网连接超时

  1. 在工作台确认 Windows 监听端口和地址没有变化。
  2. 在 Windows PowerShell 检查：netsh interface portproxy show v4tov4。
  3. 确认网络配置为 Private，防火墙规则的 RemoteAddress 是 LocalSubnet。
  4. 客户端与服务器必须在同一可互通网段；某些公司 WLAN 会启用客户端隔离。
  5. 不要把 WSL 的 172.30.* 地址给其他电脑使用；那是 NAT 内部地址。

出现 mirrored networking、无 default route 或 DNS 断链

不要继续修补 mirrored 模式。恢复默认 NAT：在 Windows PowerShell 将活动 %USERPROFILE%\.wslconfig 移走，执行 wsl --shutdown，再启动 __DISTRO__。确认 ip route 有 default via、/etc/resolv.conf 可读后再检查工作台。

Docker 拉取失败

Docker Engine 状态与 Docker Hub 网络是两件事。公司网络可能污染 Docker DNS 或重置连接；不要为了 Docker Hub 修改 WSL 全局 DNS或切换 mirrored。切换网络或配置经确认的 Docker daemon 代理。

7. 安全与回滚

  • 工作台本身只绑定回环地址；不要用额外 portproxy 把 4173 暴露到 LAN。
  • 局域网 SSH 入口只允许 Private 网络和 LocalSubnet；不要把防火墙 RemoteAddress 改成 Any，除非有明确的公网边界和额外防护。
  • 密码认证必须使用高强度、唯一的 WSL 密码；不要在网页、脚本、聊天或日志中记录它。
  • 停止入口：工作台按钮或管理员 PowerShell 执行 & "$env:USERPROFILE\.wsl-server\Configure-WslSshLan.ps1" -Disable。
  • 完整回滚：管理员 PowerShell 执行 & "$env:USERPROFILE\.wsl-server\Configure-WslSshLan.ps1" -Remove。
