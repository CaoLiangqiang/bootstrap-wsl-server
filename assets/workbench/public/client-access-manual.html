WSL __DISTRO__
访问用户手册

面向需要长期连接这台工作站的开发者。长期会话请使用个人 SSH 公钥；密码只用于首次登记或应急访问。

连接前准备：确保客户端与服务器在同一可互通局域网，向管理员确认当前 Windows LAN 地址和端口。默认端口是 __SSH_PORT__，地址可能因 DHCP 变化。

本文中的“服务器所在 Windows”指运行 WSL __DISTRO__ 的 __WINDOWS_HOSTNAME__；“用户 Windows 客户端”指实际发起 SSH 连接的另一台（或本机测试用）Windows。除非特别说明，PowerShell 命令都在用户 Windows 客户端执行。

1. 连接参数

用户名__WSL_USER__
SSH 端口__SSH_PORT__
认证密码或 SSH 公钥；root 登录禁止
地址以管理员提供的 Windows 有线/WLAN 地址为准

2. 创建个人密钥

在发起连接的客户端执行。不要把私钥文件发给任何人。

Linux/macOS/WSL

ssh-keygen -t ed25519 -a 64 -f ~/.ssh/id_ed25519_wsl_server

Windows PowerShell

推荐交互运行，看到口令提示时连续按两次 Enter，表示创建无口令私钥：

ssh-keygen -t ed25519 -a 64 -f "$env:USERPROFILE\.ssh\id_ed25519_wsl_server"
不要写 -N= 来表示空口令。在 Windows PowerShell 5.1 的参数传递中，它可能把私钥口令设置为单字符 =；私钥指纹仍会正确，直到 BatchMode 无法解锁时才暴露问题。-C=comment 也可能让注释带前导 =。

查看需要交给管理员的公钥：

cat ~/.ssh/id_ed25519_wsl_server.pub
# Windows PowerShell：
Get-Content "$env:USERPROFILE\.ssh\id_ed25519_wsl_server.pub"
只发送以 ssh-ed25519 开头的单行公钥；不要发送没有 .pub 后缀的私钥。

3. 让管理员登记公钥

  1. 通过公司认可的安全渠道把 `.pub` 文件发送给管理员，不要发送私钥。
  2. 管理员在服务器本机工作台的“访问管理 → 登录公钥”中选择该文件，核对 SHA256 指纹后确认。
  3. 管理员回传指纹；你先核对本地 `.pub` 指纹，再首次连接。
bash ~/wsl-server-workbench/scripts/add-ssh-public-key.sh /path/to/user.pub

服务器不创建独立 Linux 账号，所有公钥都登录同一个 __WSL_USER__ 账号。WebUI 只追加 authorized_keys，不会重启 SSH 或中断已有连接。若管理员暂时无法使用 WebUI，可在服务器本机运行上面的回退脚本。

登记脚本会校验 OpenSSH 格式、自动去重，并保持 ~/.ssh/authorized_keys 为 600。它不会打印公钥内容。

只把单行 .pub 文件交给管理员。持有已登记私钥的人都能以共享账号登录并获得该账号权限；离职、设备丢失或密钥泄露时立即通知管理员撤销。

4. 配置长期连接

在客户端的 ~/.ssh/config 添加：

Host __WINDOWS_HOSTNAME__-wsl
    HostName <Windows-LAN-IP>
    Port __SSH_PORT__
    User __WSL_USER__
    IdentityFile ~/.ssh/id_ed25519_wsl_server
    IdentitiesOnly yes
    IdentityAgent none
    ServerAliveInterval 30
    ServerAliveCountMax 3
    TCPKeepAlive yes

之后直接连接：

ssh __WINDOWS_HOSTNAME__-wsl

首次连接时核对管理员提供的 ED25519 主机指纹。不要为了绕过警告使用 StrictHostKeyChecking=no。

5. 文件传输与开发

scp -P __SSH_PORT__ ./file.txt __WSL_USER__@<Windows-LAN-IP>:~/
sftp -P __SSH_PORT__ __WSL_USER__@<Windows-LAN-IP>
ssh -p __SSH_PORT__ __WSL_USER__@<Windows-LAN-IP>

6. 分层验证

  1. 核对管理员回传的指纹：ssh-keygen -lf ~/.ssh/id_ed25519_wsl_server.pub。Windows PowerShell 可运行 ssh-keygen -lf "$env:USERPROFILE\.ssh\id_ed25519_wsl_server.pub"。
  2. 必要时从私钥导出公钥确认匹配（只在本机执行，不输出或发送私钥）：ssh-keygen -y -f ~/.ssh/id_ed25519_wsl_server | ssh-keygen -lf -。Windows PowerShell 同样可用对应的完整路径。
  3. 隔离 Agent 和其他身份文件，使用显式私钥测试：ssh -o BatchMode=yes -o IdentitiesOnly=yes -o IdentityAgent=none -i ~/.ssh/id_ed25519_wsl_server -p __SSH_PORT__ __WSL_USER__@<Windows-LAN-IP> "printf CODEX_SSH_OK"。
  4. 只有看到 Authenticated to ... 或远端命令输出 CODEX_SSH_OK 才算认证成功；Server accepts key 只表示公钥候选被接受，不代表签名认证已完成。
若要让 Codex 或其他后台任务无交互连接，私钥必须能在 BatchMode 下使用。无口令私钥需要依靠本机文件权限、磁盘加密和账号安全保护；如果使用带口令私钥，必须配置 Codex/Agent 能正确解锁的凭据方案，不要把口令写入脚本或网页。

7. 常见问题

Connection timed out

确认地址是 Windows LAN 地址，不是 WSL 的 172.30.* 地址；确认客户端与服务器在同一网段；让管理员检查工作台“对外端口”和 Windows Private 防火墙。

Connection refused

通常表示 WSL/sshd 未运行或 Windows portproxy 目标失效。让管理员打开工作台查看 SSH 和转发状态。

Permission denied (publickey,password)

确认使用的是对应私钥、用户名为 __WSL_USER__、管理员已登记匹配的 `.pub` 文件。先按“分层验证”核对指纹并用显式 -i、IdentitiesOnly=yes、IdentityAgent=none 重试。不要因看到 Server accepts key 就立即修改服务器：如果随后出现 sign_and_send_pubkey: signing using ssh-ed25519 仍失败，优先检查私钥是否带口令、BatchMode 是否无法解锁、实际身份文件和 SSH Agent。PowerShell 5.1 中误用 -N= 可能把口令设成 =；可用 ssh-keygen -y -P = -f <private-key> 在用户 Windows 客户端验证该假设。不要分享私钥或包含敏感信息的完整调试日志；只有管理员在服务端日志中看到对应失败记录时，才需要进一步检查 sshd 实例和认证策略。

若确认私钥口令设置有误，请在用户 Windows 客户端交互修改；按提示输入旧口令，再根据策略设置新口令：

ssh-keygen -p -f "$env:USERPROFILE\.ssh\id_ed25519_wsl_server"

修改后再次从私钥导出公钥并核对完整 SHA256 指纹，再运行隔离测试。服务端只记录 Connection closed ... [preauth] 时，也可能是客户端无法在 BatchMode 中解锁私钥；应结合客户端详细日志和服务端同一时间的记录判断。

网络或 DNS 异常

服务器使用默认 WSL NAT。不要在客户端要求服务器启用 mirrored networking；那曾导致服务器无默认路由和 DNS 断链。

8. 安全要求

  • 每位访问者使用自己的密钥，不共享私钥。
  • 私钥设置为仅本人可读：Linux/macOS 使用 chmod 600 ~/.ssh/id_ed25519_wsl_server。
  • 离职、设备丢失或密钥泄露时，立即通知管理员撤销对应公钥。
  • 不要把服务器端口转发到公网；当前防火墙设计仅允许 Private/LocalSubnet。
